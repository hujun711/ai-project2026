TypeScript 速查表写给 Java 后端工程师 — 2026-09-06

Mission: TypeScript 入门 → 全栈 → vibe coding · 配套 lesson: 你的第一个 typed function

TL;DR — 30 秒读懂 TS 对 Java 的关系

TypeScript = JavaScript 的静态类型层。它不是新语言、不是新运行时 — 编译后变成普通 JS，node 跑的是 JS。TS 给 JS 加了 Java/C# 风格的：静态类型、接口、泛型、枚举、装饰器。

你的 Java 经验 90% 可平移。TS 独有的东西（联合类型、结构化类型、类型推导、模板字面量类型）才是真正的学习对象。

1. 安装与运行

两条路

编译型（推荐先学）
npm install -g typescript   # 装 tsc
tsc hello.ts               # 编译 → hello.js
node hello.js              # 跑 JS
直接运行（开发常用）
npm install -g tsx         # 装 tsx
tsx hello.ts               # 编译 + 跑，一次完成

Java 类比：tsc ≈ javac；tsx ≈ java（直接运行字节码的运行时）。Node 跑 TS 必须先转 JS，就像 JVM 跑 .class。

tsconfig.json（最小可用）

{
  "compilerOptions": {
    "target": "ES2022",
    "strict": true,
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "outDir": "./dist",
    "rootDir": "./src",
    "esModuleInterop": true
  },
  "include": ["src/**/*"]
}

重点：strict: true 必开（相当于 Java 编译器的 -Xlint:all）。

Java 思维陷阱：String 和 string 在 TS 里不是一回事。String 是包装类（极少用），string 才是原始类型。IDE 会提示，但你容易习惯性打大写。

3. interface vs type — 什么时候用哪个

Java
public interface User {
  Long getId();
  String getName();
  int getAge();
}

public record Admin(
  Long id, String name,
  int age, String[] roles
) implements User {}
TypeScript
interface User {
  id: number;
  name: string;
  age: number;
}

// 同义两种写法
type Admin = {
  id: number;
  name: string;
  age: number;
  roles: string[];
};

const admin: Admin = {
  id: 1, name: "x",
  age: 30, roles: ["a","b"]
};

约定：对象结构用 interface（可扩展、可 implements），联合/工具/复杂类型用 type。

vibe coding 时，先写 interface 再写实现。把 interface 写在文件顶部，让 AI 看到契约再生成函数体，错误率掉一半。这是 TS 给你最大的杠杆。

4. 泛型 — 几乎和 Java 一样

Java
public <T> T first(List<T> list) {
  return list.get(0);
}

public <T extends Comparable<T>>
    T max(T a, T b) {
  return a.compareTo(b) > 0
    ? a : b;
}
TypeScript
function first<T>(list: T[]): T {
  return list[0];
}

function max<T extends
  Comparable<T>>(a: T, b: T): T {
  return a.compareTo(b) > 0
    ? a : b;
}
两个关键差异：① TS 泛型不擦除，运行时仍可用（typeof 读得到）；② TS 没有 ? extends 通配符，用 T extends unknown[] 等条件类型替代。

5. 联合类型与 narrowing — TS 独有，Java 没有

这是 TS 真正比 Java 强的地方。一个变量可以是多个类型之一：

type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "square"; side: number }
  | { kind: "rectangle"; w: number; h: number };

function area(s: Shape): number {
  // narrow: TS 看到 kind 字段自动缩小类型
  switch (s.kind) {
    case "circle":    return Math.PI * s.radius ** 2;
    case "square":    return s.side ** 2;
    case "rectangle": return s.w * s.h;
  }
  // 这里 s 是 never，TS 编译期保证穷尽
}

Java 等价物是 sealed interface + switch pattern matching（Java 21 才有）。TS 早就有了，且零运行时开销。

6. 类型守卫（narrowing 的工具）

function process(v: string | number | null) {
  // typeof 守卫
  if (typeof v === "string") return v.toUpperCase();

  // instanceof 守卫
  if (v instanceof Date) return v.toISOString();

  // in 守卫（结构化类型特有）
  if (v && "id" in v) return v.id;

  // 自定义类型谓词
  if (isUser(v)) return v.name;
}

function isUser(x: any): x is User {
  return x && typeof x.id === "number";
}

7. any vs unknown vs never

类型能赋值给其他？能使用前需要？Java 类比
any✅ 万能❌ 直接用Object 上界 + 关掉所有检查
unknown❌ 必须先 narrow✅ narrow 后类型安全的 Object，但要先 instanceof/typeof
never✅ 任何类型不可能使用无返回值的 void、抛异常的函数
Java 思维陷阱：Java 里能往 Object 塞任何东西然后强转，TS 里 unknown 才是这个模式，any 是关闭类型检查（逃课按钮）。优先 unknown。

8. Promise vs Future — 异步几乎一样

Java
CompletableFuture<String> fetch()
  = CompletableFuture
      .supplyAsync(() -> http());

String data = fetch()
  .thenApply(String::toUpperCase)
  .join();
TypeScript
async function fetch(): Promise<string> {
  return await http();
}

const data = await fetch()
  .then(s => s.toUpperCase());

差别：TS 的 await 是语言级语法（比 Java 链式调用简洁 10 倍），但底层仍是事件循环 + 单线程。高 CPU 计算仍是 Node 痛点。

9. 模块系统 — CommonJS vs ESM

// 旧 Node（CommonJS）
import x = require("./x");

// 现代（ES Module）— 推荐
import { foo, bar } from "./x";
import * as X from "./x";
import type { Foo } from "./x";   // 仅类型，运行时擦除

export function foo() {}
export default class Bar {}

vs Java：Java 的 import 只导入类型，运行时靠 classpath；TS 的 import 同时导入类型和值（除非用 import type）。这导致 TS 代码里循环依赖更危险。

10. 工具类型（TS 独有，AI 友好）

工具类型作用vibe coding 用法
Partial<T>所有字段变可选更新对象（PATCH）
Required<T>所有字段变必填补全缺字段
Pick<T, K>挑出指定字段列表项只展示部分字段
Omit<T, K>删掉指定字段创建对象时去除敏感字段
Record<K, V>键值对类型字典、配置对象
ReturnType<T>取函数返回类型派生类型不重写
Readonly<T>所有字段只读不可变数据
让 Claude Code 生成代码时，如果你给 type UserInput = Omit<User, "id" | "createdAt"> 这种派生类型，AI 会自动复用而不会重新定义。少写 30% 代码。

11. as const 与字面量类型 — 类型体操的入口

// 不加 as const：推断为 string[]
const routes = ["/", "/about", "/contact"];

// 加 as const：变成 readonly 字面量元组
const routes = ["/", "/about", "/contact"] as const;
// 类型：readonly ["/", "/about", "/contact"]

type Route = typeof routes[number];
// 类型："/" | "/about" | "/contact"

Java 完全无对应。这是 TS 类型体操的入口，配合 typeof、keyof、infer 能写出惊人强大的类型。

12. Vibe coding 实战 — 用 TS interface 当「AI 脚手架」

这是你最该养成的习惯。在让 AI 生成函数体前，先手写接口：

// 1. 手写接口（你的意图）
interface CreateOrderInput {
  userId: number;
  items: { sku: string; qty: number }[];
  couponCode?: string;
}

interface OrderResult {
  orderId: string;
  total: number;
  createdAt: Date;
}

// 2. 让 AI 生成函数体
async function createOrder(
  input: CreateOrderInput
): Promise<OrderResult> { /* ... */ }

AI 看到契约后，几乎不会返回错误类型。这是 TS 在 vibe coding 时代最大的杠杆 — 类型就是给 LLM 的精确 prompt。
