LESSON 0001你的第一个 typed function15 分钟跑通 · 不需要任何前端基础

对齐 MISSION · 配套速查表 TS for Java Devs · 前置：Node.js ≥ 18 已安装 · 后续：Lesson 0002（type inference）

这节课你只做一件事：在本地写一个带类型的函数，编译并运行。15 分钟内完成。结束时的可运行成果 = 你写出了第一个 TypeScript 程序。

步骤

检查 Node.js（30 秒）

打开终端（PowerShell / Git Bash / 任何 shell），跑：

node --version
# 期望：v18 或更高（v20+ 更佳）

如果版本低于 18，去 nodejs.org 下载 LTS 安装。

安装 TypeScript 编译器（1 分钟）

npm install -g typescript

# 验证
tsc --version
# 期望：Version 5.x 或更高

如果 tsc 报「command not found」，参考下方「Windows PATH 问题」侧记。

创建项目目录（30 秒）

mkdir ts-hello
cd ts-hello
mkdir src
code .  # 或任何编辑器打开

写第一个 typed function（5 分钟）

在 src/hello.ts 写入下面这段代码。每一行都对照 Java 看，你会立刻懂。

// ============================================
// 你的第一个 typed function
// 目标：把 Java 的 "Hello, x" 习惯平移到 TS
// ============================================

// Java:  public static String greet(String name, int age) { ... }
// TS:     函数参数 + 返回值都标注类型

function greet(name: string, age: number): string {
  return `Hello, ${name}! You are ${age} years old.`;
}

// 调用（参数类型错就编译报错）
console.log(greet("hujun", 30));
console.log(greet("TypeScript", 8));

// 试着解注释这行，看 tsc 怎么报错：
// console.log(greet(123, "thirty"));

注意两个细节：

  1. 小写 string，不是 String。TS 类型全小写。
  2. 模板字符串用反引号 `，里面 ${...} 插值 — 类似 Java 15+ 的 text blocks 但更轻。

编译并运行（2 分钟）

方式 A — 编译型（推荐先体验编译过程）：

npx tsc src/hello.ts
# 产出 src/hello.js

node src/hello.js
# 输出：
# Hello, hujun! You are 30 years old.
# Hello, TypeScript! You are 8 years old.

方式 B — 直接运行（开发时常用）：

npm install -g tsx
tsx src/hello.ts
# 同样的输出，跳过中间 .js 文件

体验类型检查的力量（2 分钟）

把 Step 4 最后一行解注释（传错类型），重新跑 npx tsc src/hello.ts，看错误：

src/hello.ts:14:23 - error TS2345:
  Argument of type 'number' is not assignable
  to parameter of type 'string'.

14   console.log(greet(123, "thirty"));

这是 TS 给你的第一份礼物：编译期就抓到错，不需要等到运行时崩溃。对比 Java 行为几乎一致。

🏁 你完成了
  • 安装了 TS 工具链（tsc / tsx）
  • 写了一个带类型的函数
  • 看到了编译期类型检查报错
  • 理解了 TS 是「Java 的类型 + JavaScript 的灵活」

Java vs TS 第一印象对比

维度JavaTypeScript（你这步写的）
类型声明 String name name: string（小写，位置在变量名后）
字符串模板 "Hello, " + name `Hello, ${name}`
编译产物 .class 字节码 .js 普通 JS（类型擦除）
编译期类型检查 默认开 需要 strict: true 才全开
运行时 JVM Node.js / Bun（V8 引擎）
vibe coding 时刻：你现在写的这个函数，如果粘贴到 Claude Code / Cursor 的 prompt 里，让 AI「加一个 farewell 函数，签名同 greet」，AI 100% 会给出带正确类型的版本。TS 类型是给 LLM 的精确 prompt — 这是你 Java 经验升级而不是降级的杠杆。

常见问题

Windows 下 tsc 报「command not found」

npm 全局安装路径不在 PATH。两种修法：

# 1. 看 npm 全局 bin 在哪
npm config get prefix
# 把输出的 \node_modules\.bin 加到系统 PATH，然后重启终端

# 2. 或者直接用 npx 调用（无需全局安装）
npx tsc src/hello.ts
tsc 报「Cannot find module 'typescript'」

需要本地也装一份：

npm init -y
npm install --save-dev typescript
npx tsc src/hello.ts
为什么需要 tsx 而不是直接 node 跑 .ts？

Node 24+ 开始原生支持 --experimental-strip-types 跑 .ts。但生产环境、社区习惯、IDE 调试等都依赖 tsc/tsx。装 tsx 是为了一行命令搞定。
