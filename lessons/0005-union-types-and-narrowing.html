LESSON 0005联合类型与 Narrowing30 分钟 · TS 比 Java 强的地方

对齐 MISSION · CURRICULUM · 前置：L0004 · 后续：L0006

这是 TS 真正比 Java 优雅的地方。Java 用 sealed interface + switch pattern matching 模拟（Java 21 才稳定），TS 一开始就有，且零运行时开销。

联合类型：值可以是多个类型之一

// 基础联合
let value: string | number;
value = "hello";   // ✅
value = 42;        // ✅
value = true;      // ❌ TS 报错

// 字面量联合（最常用）
type Status = 'pending' | 'active' | 'banned';
type Direction = 'up' | 'down' | 'left' | 'right';

// 对象联合
type Result =
  | { ok: true; value: number }
  | { ok: false; error: string };

Java 类比：
TS string | number ≈ Java 的 Object 上界，但 TS 不需要 instanceof 就能在编译期限制可赋的值。
TS discriminated union ≈ Java 21 sealed interface + permits + switch pattern，但 TS 从第一天就有。

Narrowing：让 TS 在分支里「缩小」类型

typeof 守卫（原始类型）

function padLeft(value: string | number, padding: number): string {
  if (typeof value === "string") {
    // 这里 value 被缩窄为 string
    return " ".repeat(padding) + value;
  }
  // 这里 value 被缩窄为 number
  return " ".repeat(padding) + value.toString();
}

in 守卫（对象字段）

type Fish = { swim: () => void };
type Bird = { fly: () => void };

function move(animal: Fish | Bird) {
  if ("swim" in animal) {
    animal.swim();  // 缩窄为 Fish
  } else {
    animal.fly();   // 缩窄为 Bird
  }
}

instanceof 守卫（类实例）

function logError(e: Error | string) {
  if (e instanceof Error) {
    return e.message;   // 缩窄为 Error
  }
  return e;             // 缩窄为 string
}

自定义类型谓词（最灵活）

interface User { id: number; name: string }

function isUser(x: unknown): x is User {
  return typeof x === "object" &&
         x !== null &&
         "id" in x &&
         typeof (x as any).id === "number";
}

// 用法
const data: unknown = JSON.parse(someStr);
if (isUser(data)) {
  console.log(data.name);   // TS 知道 data 是 User
}

Discriminated Union：state machine 的标准写法

这是 TS 最强大的模式，AI 写 React state / API response 都靠它：

// =============================================
// 异步加载状态机（Next.js / React 高频）
// =============================================
type AsyncState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; error: Error };

// 渲染组件时根据 status narrow
function render<T>(state: AsyncState<T>) {
  switch (state.status) {
    case 'idle':
      return null;
    case 'loading':
      return 'Loading...';
    case 'success':
      return state.data;      // TS 知道 data 存在
    case 'error':
      return state.error.message;
    // 不需要 default！TS 知道已穷尽所有 case
  }
}

穷尽性检查 — TS 帮你兜底

type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'square'; side: number };

function area(s: Shape): number {
  switch (s.kind) {
    case 'circle': return Math.PI * s.radius ** 2;
    case 'square': return s.side ** 2;
    // 假设你忘了处理 circle：
    // TS 不报错，但 s 可能是 never
  }
}

// 加 assertNever 兜底
function assertNever(x: never): never {
  throw new Error("Unhandled: " + JSON.stringify(x));
}

function areaSafe(s: Shape): number {
  switch (s.kind) {
    case 'circle': return Math.PI * s.radius ** 2;
    case 'square': return s.side ** 2;
    default: return assertNever(s);  // 漏 case 时 TS 编译期报错
  }
}
vibe coding 实战：
  • 状态机 = discriminated union：让 AI 用 type State = { kind: ... } | { kind: ... } 写，AI 几乎能自动写出穷尽的 switch
  • API response 必用：{ status: 'ok'; data: X } | { status: 'err'; error: string }，AI 写前端组件时会按 status 分支渲染
  • 想偷懒就用 unknown + 自定义谓词：解析外部数据（JSON.parse、localStorage）时先 narrow，比类型断言安全
读 Next.js 源码，看到 status:、kind:、type: 这种判别字段，就是 discriminated union。
