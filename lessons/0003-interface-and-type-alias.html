LESSON 0003Interface & Type Alias25 分钟 · 学会区分「用什么」

对齐 MISSION · CURRICULUM · 前置：L0002 · 后续：L0004

TS 有两个「定义类型」的关键字：interface 和 type。90% 场景可以互换，但社区有明确惯例。读 AI 代码、看库的类型声明，第一眼要分清这俩。

什么时候用哪个 — 一张表搞定

场景用原因
对象/类的契约interface可 extends、可 implements、可声明合并
联合类型（|）typeinterface 不支持 |
交叉类型（&）typeinterface 不支持 &
工具类型派生（Pick<>）typeinterface 不能 = 一个表达式
函数类型两者皆可社区偏向 type（更简洁）
原始类型别名（type ID = string）typeinterface 不能给原始类型起别名

Java 类比：
interface User { ... } ≈ public interface User { ... } — 都是"对象契约"。
Java 没有的：type Status = 'a' | 'b' | 'c' ≈ sealed interface + 三个子类，更轻量。

Demo：完整对象契约样板

复制到 src/user.ts：

// =============================================
// 对象契约 → interface
// =============================================
interface User {
  id: number;
  name: string;
  email?: string;            // 可选字段
  readonly createdAt: Date;  // 只读
}

// 继承（extends = Java 的 extends）
interface Admin extends User {
  permissions: string[];
}

// =============================================
// 命名类型/联合 → type
// =============================================
type Status = 'pending' | 'active' | 'banned';
type ID = string | number;
type UserWithStatus = User & { status: Status };

// =============================================
// 工具类型派生 → 必须用 type
// =============================================
type UserInput = Omit<User, 'id' | 'createdAt'>;
type UserPatch = Partial<User>;

interface 的两个独有特性

① 声明合并（declaration merging）

// 同 interface 多次声明会自动合并
interface User { id: number; name: string; }
interface User { email?: string; }

// 等价于：
// interface User {
//   id: number;
//   name: string;
//   email?: string;
// }

// 用法：扩展第三方库的类型（很常见）
interface Window { myCustomProp: string }

② implements（class 实现）

class UserService implements User {
  constructor(
    public id: number,
    public name: string,
    public createdAt: Date
  ) {}

  // email 可选，不需要实现
}

type 能做但 interface 不能的 3 件事

① 联合 / 交叉

type StringOrNumber = string | number;
type Combined = { a: string } & { b: number };
// Combined = { a: string; b: number }

② 条件类型 / 模板字面量

type IsString<T> = T extends string ? true : false;
type Greet<Name extends string> = `hello, ${Name}`;
// Greet<"world"> = "hello, world"

③ 工具类型派生

type UserKeys = keyof User;       // "id" | "name" | "email" | "createdAt"
type UserValues = User[keyof User]; // number | string | Date | undefined
vibe coding 实战：
  • 写函数签名 → 先写 interface 表达「我要的对象形状」
  • 写状态机 → 用 type Status = 'pending' | ... 让 AI 写出穷尽的 switch
  • 扩展 AI 给的 interface → 用 interface X extends Y，比 type X = Y & {...} 更直观
读 Next.js 代码时，看到 interface Props 就是组件 prop 契约；看到 type 多半是联合或工具派生。
