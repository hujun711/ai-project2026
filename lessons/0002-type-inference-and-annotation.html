LESSON 0002类型推导 vs 显式标注20 分钟 · 3 个判断标准

对齐 MISSION · CURRICULUM · 前置：L0001 · 后续：L0003

TS 的默认行为是推导，不是要求标注。这与 Java 完全不同 — Java 必须显式写类型，TS 不写也能跑。学会什么时候标注比学语法重要 — 因为 AI 生成的代码常常省略标注，你需要知道省略是否安全。

核心规则（3 条够了）

场景该标注吗原因
函数参数 必须 TS 不会从上下文推参数类型，漏写 = any
函数返回值 可选 TS 会从 return 语句推导，显式标注当文档用
变量初值 能不写就不写 推导的字面量类型更精确（如 5 而非 number）

Java 类比：Java 10+ 的 var 就是 TS 推导。差别是 TS 推导贯穿整个项目（贯穿函数边界），Java 的 var 只在局部变量。
TS 字面量类型 ≈ final int MAX = 100 中 100 的类型 — 但 TS 会自动推得更窄。

Demo：3 段对比

复制到 src/inference.ts，跑 tsx src/inference.ts：

// =============================================
// 1. 变量：让 TS 推导，不要手写
// =============================================
let name = "hujun";        // 推导为 string
const age = 30;            // 推导为 30（字面量，不是 number！）
const status = "active";   // 推导为 "active"（不是 string！）

// 反例（不要这样写）：
// let name: string = "hujun";   // 重复 — TS 已经知道

// =============================================
// 2. 函数：参数必须标，返回值看心情
// =============================================

// ❌ 错的（参数没标，TS 静默放行 a=any, b=any）
// function add(a, b) { return a + b; }

// ✅ 正确写法
function add(a: number, b: number) {
  return a + b;   // 返回类型 TS 推导为 number
}

// 想把返回类型当文档写？也行
function greet(name: string): string {
  return `Hello, ${name}`;
}

// =============================================
// 3. 对象/数组：初值歧义时显式标
// =============================================

// 没有初值 → TS 推 any，必须标
let userInput: { name: string; age: number };
userInput = { name: "x", age: 30 };

// 有初值 → TS 推导够用
const config = {
  port: 3000,        // 推导为 3000
  debug: true,       // 推导为 true
};

// 想让 TS 推更宽的类型（比如 port 真的是 number）
const config2: { port: number; debug: boolean } = {
  port: 3000,
  debug: true,
};

3 个易错点

① const 推字面量类型 — 重要！

const x = 5;          // 类型：5（不是 number！）
let y = 5;            // 类型：number

// 想让 const 推成 number？两种办法：
const z: number = 5;              // 显式标
const w = 5 as number;            // 类型断言

// 这会影响函数参数匹配：
function expectNumber(n: number) {}
expectNumber(x);  // ❌ 错！5 不是 number

② 函数返回 null / undefined 的隐性陷阱

// 推导返回类型可能漏掉 undefined
function find(id: number) {
  if (id < 0) return;
  return { id, name: "x" };
}
// TS 推导返回类型：{ id: number; name: string } | undefined
// 你以为它一定返回对象，实际可能 undefined — 加 strictNullChecks 后编译器会提醒

③ as const 把对象/数组变成只读字面量

// 普通数组
const routes = ["/", "/about"];       // 类型：string[]
const routesConst = ["/", "/about"] as const;
// 类型：readonly ["/", "/about"]

// 配合 typeof 取字面量联合
type Route = typeof routesConst[number];
// 类型："/" | "/about"
vibe coding 实战：让 Claude Code 写代码时——
  • 函数签名：你写清楚（参数 + 返回类型）→ AI 写实现
  • 变量初值：你给一个有代表性的值 → AI 不必重复
  • 想要字面量类型：明确告诉 AI "用 as const"，否则它会默认 string
类型是给 LLM 的 prompt — 标注清楚 = 任务边界清晰，AI 错误率降低。

Quiz 自测（5 题）

  1. const x = 5; 的类型是？
    A. number   B. 5（字面量）  C. any   D. unknown
  2. function add(a, b) { return a + b; } 会怎样？
    A. 编译通过，a/b 是 number   B. 编译错误   C. 编译通过，但 a/b 是 any   D. 自动推断为 string
  3. 哪个场景必须显式标注类型？
    A. let x = 5   B. 函数参数   C. const y = "hi"   D. return 42
  4. 想让 const 数组保留精确字面量类型，应该？
    A. as const   B. : string[]   C. : Array<string>   D. 不可能
  5. vibe coding 时，让 AI 写函数体，你应该？
    A. 只描述意图   B. 给完整函数签名（参数 + 返回类型）   C. 让 AI 自己决定   D. 不写函数
答案

1. B（字面量 5） · 2. C（参数变 any） · 3. B（函数参数） · 4. A（as const） · 5. B（完整函数签名）
