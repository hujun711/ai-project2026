Next.js 项目打开一堆 import 和一个 tsconfig.json。这节课让你知道每行什么意思，看到 @/ 别懵，看到 import type 知道是只类型，看到 tsconfig.json 关键字段不再发怵。

ES Module 语法速读

// =============================================
// 命名导出（推荐）
// =============================================
// utils.ts
export function add(a: number, b: number) { return a + b; }
export const PI = 3.14;
export interface User { id: number; name: string }
export type Status = 'ok' | 'err';

// main.ts
import { add, PI } from "./utils";
import type { User, Status } from "./utils";   // 只导类型，运行时无开销

// =============================================
// 默认导出（一个文件一个主类/主组件时用）
// =============================================
// Button.tsx
export default function Button() { ... }

// 任意名字导入
import Button from "./Button";
import Btn from "./Button";   // 都可以

// =============================================
// 命名空间导入
// =============================================
import * as utils from "./utils";
utils.add(1, 2);

// =============================================
// 重新导出（barrel 文件常用）
// =============================================
// index.ts
export { add } from "./math";
export { Button } from "./Button";
export * from "./types";

Java 类比：
export ≈ public 类/方法；不 export = package-private。
Java 的 import 只导入类型；TS 的 import 同时导入类型和值（运行时还要用）。这就是为什么需要 import type 来明确"我只要类型"。

import type — TS 独有，关键

// 普通 import：类型 + 值都打包进 bundle
import { User } from "./types";

// import type：只在编译期用，运行时整行消失
import type { User } from "./types";

// Next.js / tRPC 大量用 import type 优化打包体积
import type { NextPage } from "next";
import type { AppRouter } from "./server/router";

// 整模块只类型
import type * as Types from "./types";

tsconfig.json 关键字段（看 Next.js 必备）

{
  // === 必看 4 个 ===
  "target": "ES2022",            // 编译到哪个 JS 版本
  "module": "ESNext",            // 模块系统
  "moduleResolution": "Bundler", // Next.js 用 Bundler（Vite/Webpack 也用）
  "strict": true,                // 全套严格检查（强烈推荐开）

  // === Next.js 常见 ===
  "jsx": "preserve",             // JSX 不编译，让 Next 处理
  "incremental": true,           // 增量编译，加速
  "esModuleInterop": true,       // 允许 import React from "react"

  // === 路径别名（看到 @/ 就靠它）===
  "baseUrl": ".",
  "paths": {
    "@/*": ["./src/*"],          // @/components → ./src/components
    "~//*": ["./*"]
  },

  // === 类型根目录 ===
  "include": ["next-env.d.ts", "**/*.ts", "**/*.tsx"],
  "exclude": ["node_modules"]
}

strict: true 包含哪些子项

字段作用
noImplicitAny禁止隐式 any（参数漏标类型就报错）
strictNullChecksnull / undefined 必须显式处理
strictFunctionTypes函数类型严格校验
strictBindCallApplybind/call/apply 类型严格
strictPropertyInitializationclass 字段必须初始化
noImplicitThisthis 类型必须明确
alwaysStrict每个文件自动加 "use strict"
useUnknownInCatchVariablescatch (e) 的 e 是 unknown（必须 narrow）

读懂 Next.js 项目结构的 5 步

my-nextjs-app/
├── app/                          # App Router（Next.js 13+）
│   ├── layout.tsx
│   ├── page.tsx
│   └── api/
│       └── users/route.ts        # 后端 API
├── components/                   # 共享组件
├── lib/                          # 工具函数
├── prisma/                       # Prisma schema（Drizzle 类似）
├── tsconfig.json                 # ← 关键
├── next.config.js
├── package.json
└── next-env.d.ts                 # Next 自动生成，类型辅助

看到 tsconfig.json 里 "paths": { "@/*": ["./src/*"] }，那 import { foo } from "@/lib/foo" 就是从 src/lib/foo 取。

vibe coding 实战：
  • 看到 import type：知道运行时无开销，是纯类型 — AI 大量用做类型导入优化
  • 看到 @/ 开头的 import：路径别名，去 tsconfig.json 的 paths 字段找映射
  • 让 AI 改 Next.js 项目前：自己先打开 tsconfig.json 看 strict 和 paths，告诉 AI 当前配置
  • AI 给的代码 import 报错？99% 是路径错（漏 @/ 或文件后缀），10% 是 tsconfig.json 没配对应 alias

Quiz 自测（5 题）

  1. import type 与 import 的关键区别？
    A. import type 只能从 .d.ts 文件导入   B. import type 运行时无开销（编译期擦除）   C. import type 必须显式声明
  2. 默认导出命名限制？
    A. 必须叫 default   B. 导入时可任意命名   C. 一个文件只能有一个
  3. tsconfig.json 的 paths 字段干啥的？
    A. 编译目标   B. 路径别名映射   C. 严格模式
  4. strict: true 不包含？
    A. noImplicitAny   B. strictNullChecks   C. noUnusedLocals（这个不在 strict 里）
  5. 看到 import { foo } from "@/lib/foo" 但编译报「cannot find module」？
    A. foo.ts 不存在   B. tsconfig.json 没配 @/ alias   C. 两者都可能
答案

1. B · 2. B · 3. B · 4. C · 5. C
