AI 写的代码（完整版）

假装这段是 Claude Code 给你的，需求是「写一个获取用户列表的 API 路由 + 前端组件」：

// =============================================
// app/api/users/route.ts
// =============================================
import { db } from "@/lib/db";

export async function GET(request) {
  const users = await db.user.findMany();
  return Response.json(users);
}

// =============================================
// app/users/page.tsx
// =============================================
"use client";

import { useState, useEffect } from "react";

interface User {
  id: number;
  name: string;
  email: any;
}

export default function UsersPage() {
  const [users, setUsers] = useState([]);
  const [error, setError] = useState();

  useEffect(() => {
    fetch("/api/users")
      .then(res => res.json())
      .then(data => setUsers(data));
  }, []);

  return (
    <div>
      {users.map(u => (
        <div key={u.id}>
          <h3>{u.name}</h3>
          <p>{u.email.toUpperCase()}</p>
        </div>
      ))}
    </div>
  );
}

5 个 Bug — 先自己找

对照 L0001-L0007 的概念，逐行扫一遍。你能找出几个？

🐛 Bug 1：API route 缺类型（对应 L0001）

问题：export async function GET(request) 漏了 request: Request 类型，TS 会把 request 推成 any。

修法：

export async function GET(request: Request) { ... }

vibe coding 教训：永远给函数参数加类型，AI 经常漏。

🐛 Bug 2：email: any（对应 L0004 + L0007）

问题：email 应该是 string 或 string | null，any 关掉了类型检查，运行时 u.email.toUpperCase() 会因为 email 是 undefined 崩溃。

修法：

interface User {
  id: number;
  name: string;
  email: string | null;   // 或 string，看 DB schema
}
🐛 Bug 3：useState([]) 推导成 never[]（对应 L0002 + L0005）

问题：useState([]) 推导成 never[]（空数组字面量），后面 users.map(u => ...) 里 u 是 never，u.name 报错。

修法：

const [users, setUsers] = useState<User[]>([]);
🐛 Bug 4：useState() 缺初值（对应 L0007 + strictNullChecks）

问题：useState() 不传初值 = undefined。strict: true 下，error 类型是 undefined，后面 setError(...) 调用没问题，但读 error 会报错。

修法：

const [error, setError] = useState<Error | null>(null);
🐛 Bug 5：fetch 无错误处理 + 无 await（对应 L0006 + L0005）

问题：① fetch 失败时 res.json() 不被调用；② 没 await，TS 不报但写法不规；③ 错误被静默吃掉，UI 上看不到失败。

修法（用 Result 类型）：

useEffect(() => {
  async function load() {
    try {
      const res = await fetch("/api/users");
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
      const data: User[] = await res.json();
      setUsers(data);
    } catch (e) {
      setError(e as Error);
    }
  }
  load();
}, []);

更地道的写法：让 API 返回 Result<T>，前端按状态分支渲染（见 L0005）。

修好后的完整版

// =============================================
// app/api/users/route.ts
// =============================================
import { db } from "@/lib/db";

interface User {
  id: number;
  name: string;
  email: string | null;
}

export async function GET(request: Request) {
  const users: User[] = await db.user.findMany();
  return Response.json(users);
}

// =============================================
// app/users/page.tsx
// =============================================
"use client";

import { useState, useEffect } from "react";

interface User {
  id: number;
  name: string;
  email: string | null;
}

type LoadState =
  | { status: 'loading' }
  | { status: 'success'; users: User[] }
  | { status: 'error'; error: string };

export default function UsersPage() {
  const [state, setState] = useState<LoadState>({ status: 'loading' });

  useEffect(() => {
    async function load() {
      try {
        const res = await fetch("/api/users");
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        const users: User[] = await res.json();
        setState({ status: 'success', users });
      } catch (e) {
        setState({ status: 'error', error: (e as Error).message });
      }
    }
    load();
  }, []);

  if (state.status === 'loading') return <p>加载中...</p>;
  if (state.status === 'error') return <p>出错: {state.error}</p>;
  return (
    <div>
      {state.users.map(u => (
        <div key={u.id}>
          <h3>{u.name}</h3>
          <p>{u.email ?? '无邮箱'}</p>
        </div>
      ))}
    </div>
  );
}

5 个 vibe coding 黄金规则（综合 L0001-L0007）

  1. 先写接口再让 AI 写实现（L0003）— 类型是给 LLM 的 prompt
  2. 工具类型派生输入输出（L0004）— Omit<User, 'id'> 别让 AI 重抄字段
  3. 异步用 Result<T> 表达错误（L0005 + L0006）— 不要 throw 让上层吞
  4. discriminated union 写状态机（L0005）— 加载/成功/失败/空都靠它
  5. 永远检查 AI 的类型推导（L0002）— useState([]) 变 never[] 是高频坑
实战检验：现在打开 Claude Code 或 Cursor，粘贴上面那段「修好后的完整版」代码，输入 prompt：

"请基于这段代码加一个新功能：搜索框，按 name 过滤用户列表。要求：(1) 用 TypeScript strict 模式；(2) 输入类型用 User 派生；(3) 过滤用 discriminated union 表达 loading/empty/hasResults 三个状态"

观察 AI 输出：
  • 是否把搜索状态做成 union？
  • 是否复用 User 类型？
  • 是否处理了「输入为空」和「结果为空」的区分？
这些检查点都是 vibe coding 时代的「单元测试」。

Quiz 自测（5 题）

  3. useState() 不传初值的类型是？

  4. vibe coding 想让 AI 写状态机？
