LESSON 0004泛型与工具类型30 分钟 · 读懂 90% 库的类型签名

对齐 MISSION · CURRICULUM · 前置：L0003 · 后续：L0005

读 React / Next.js / tRPC 源码，你会不停看到 <T>、Pick<X, K>、Partial<X>、Omit<X, K>。这节课让你能读这些符号，而不是手写它们。

泛型：几乎和 Java 一样（一个关键差别）

// 基础泛型
function identity<T>(value: T): T {
  return value;
}
const r1 = identity<string>("hello");   // 显式指定
const r2 = identity(42);                 // TS 推 T = number

// 约束（extends ≈ Java 的 extends Comparable）
function longest<T extends { length: number }>(a: T, b: T): T {
  return a.length >= b.length ? a : b;
}

Java 类比：<T extends ...> 语法几乎一致。
关键差别：TS 泛型不擦除，运行时还能读到类型元数据（通过 Symbol.toStringTag）。Java 泛型是擦除的，运行时 List<String> 和 List<Integer> 是同一个类。

工具类型速查（5 个就够覆盖 90% 场景）

工具类型作用典型场景
Partial<T>所有字段可选更新对象（PATCH）
Required<T>所有字段必填补全 ?: 漏掉的字段
Pick<T, K>选指定字段列表项只展示部分字段
Omit<T, K>排除指定字段创建对象时去除 id / createdAt
Record<K, V>键值对类型字典 / 配置对象

Demo：读懂真实代码

复制到 src/user-types.ts：

// =============================================
// 基础类型（你定义）
// =============================================
interface User {
  id: number;
  name: string;
  email: string;
  age: number;
  createdAt: Date;
}

// =============================================
// 工具类型派生（让 AI 别重复定义）
// =============================================

// 创建用户时不传 id 和 createdAt（数据库生成）
type UserInput = Omit<User, 'id' | 'createdAt'>;
// 等价于：{ name: string; email: string; age: number; }

// 更新用户时所有字段都可选
type UserPatch = Partial<User>;
// 等价于：{ id?: number; name?: string; ... }

// 列表项只展示 id + name
type UserSummary = Pick<User, 'id' | 'name'>;
// 等价于：{ id: number; name: string; }

// 用户字典（按 id 索引）
type UserMap = Record<number, User>;
// 等价于：{ [key: number]: User }

// =============================================
// 派生函数返回类型（不用手抄）
// =============================================
function getUser() {
  return { id: 1, name: 'hujun' };
}

type GetUserReturn = ReturnType<typeof getUser>;
// 自动派生：{ id: number; name: string }

// =============================================
// 实战：拼装出来的完整 API 签名
// =============================================
async function createUser(
  input: UserInput
): Promise<User> {
  // ... 让 AI 写实现
  return { ...input, id: 1, createdAt: new Date() };
}

async function updateUser(
  id: number,
  patch: UserPatch
): Promise<User> {
  // ... 让 AI 写实现
  return {} as User;
}

async function listUsers(): Promise<UserSummary[]> {
  // ... 让 AI 写实现
  return [];
}

嵌套泛型怎么读（实战高频）

// Next.js 的页面 props 类型
type PageProps<TParams = {}> = {
  params: TParams;
  searchParams: { [key: string]: string | string[] | undefined };
};

// tRPC 的 query hook
type UseQueryResult<TData, TError> = {
  data: TData | undefined;
  error: TError | null;
  isLoading: boolean;
};

// 读法：从外到内，先看「这个类型干什么」，再看「T 是什么」
// 例：UseQueryResult<User, Error>
// → 返回 { data: User | undefined; error: Error | null; ... }

3 个常见泛型错误代码

① 把 Array 和数组字面量搞混

function first(arr: Array<string>): string { return arr[0]; }
function firstAlt(arr: string[]): string { return arr[0]; }
// 等价。第二种更常用、更短。

② 约束写错位置

// ❌ 错
function f<T>(x: T extends number): void {}

// ✅ 对
function f<T extends number>(x: T): void {}

③ 默认值语法（Java 没有）

type PageProps<TParams = Record<string, never>> = { params: TParams };
// 不传时 params 是空对象 {}
vibe coding 实战：
  • 派生类型用工具类型，别让 AI 重新定义 → type X = Omit<User, 'id'> 比 type X = { name: string; email: string; ... } 强 10 倍
  • 读库签名时，用鼠标 hover 任何泛型参数，IDE 会告诉你具体类型 — 不必死记
  • 让 AI 实现函数体前，先用 Pick/Omit/Partial 派生出输入输出类型，AI 几乎不会返错

Quiz 自测（5 题）

  1. Pick<User, 'id' | 'name'> 等价于？
    A. { id?: number; name?: string; }   B. { id: number; name: string; }   C. User
  2. Omit<User, 'id' | 'createdAt'> 等价于？
    A. Pick<User, 'id' | 'createdAt'>   B. User 去掉 id 和 createdAt   C. User 的所有字段变可选
  3. Partial<T> 把 T 的字段变成？
    A. 可选   B. 必填   C. 只读
  4. ReturnType<typeof f> 拿什么？
    A. f 的参数类型   B. f 的返回类型   C. f 的名字
  5. TS 泛型和 Java 泛型的关键差别？
    A. TS 不支持   B. TS 运行时仍保留类型元数据（不擦除）   C. TS 性能更差
答案

1. B · 2. B · 3. A · 4. B · 5. B
