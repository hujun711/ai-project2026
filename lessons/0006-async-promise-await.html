对齐 MISSION · CURRICULUM · 前置：L0005 · 后续：L0007

读 Next.js / tRPC 代码，async 函数无处不在。这节课让你能读懂异步链：返回类型、错误处理、并发控制。Java 已经有 CompletableFuture，TS 的 Promise 类似但语法更简洁。

3 个核心概念

概念作用Java 类比
Promise<T>表示「未来某个时刻会有 T 类型的值」CompletableFuture<T>
async声明函数返回 Promise方法返回 CompletableFuture
await等待 Promise 解决（resolve），取出值.join() / .get()

TS await 是语言级语法，不是方法调用。这意味着：
① 写法像同步代码，更易读
② 只能在 async 函数里用
③ TS 知道 await 后的值的类型，不用链式 .then() 推导

Demo：完整异步样板

复制到 src/fetch-user.ts：

// =============================================
// 1. 基础 async / await
// =============================================

interface User {
  id: number;
  name: string;
  email: string;
}

async function fetchUser(id: number): Promise<User> {
  const res = await fetch(`/api/users/${id}`);
  if (!res.ok) {
    throw new Error(`HTTP ${res.status}`);
  }
  return res.json();   // 返回 User（TS 推）
}

// =============================================
// 2. 并行请求（高频用法）
// =============================================

async function fetchUserAndPosts(userId: number) {
  // 同时发起两个请求，等两个都完成
  const [user, posts] = await Promise.all([
    fetchUser(userId),
    fetchPosts(userId),
  ]);
  return { user, posts };
}

// 不关心失败？用 allSettled
const results = await Promise.allSettled([fetchUser(1), fetchUser(2)]);
// results: PromiseSettledResult<User>[]

// =============================================
// 3. 错误处理（必会）
// =============================================

// 方式 A：try/catch
async function safeGetUser(id: number): Promise<User | null> {
  try {
    return await fetchUser(id);
  } catch (e) {
    console.error("Failed to fetch user:", e);
    return null;
  }
}

// 方式 B：用 Result 类型（推荐 vibe coding）
type Result<T> =
  | { ok: true; value: T }
  | { ok: false; error: Error };

async function getUserResult(id: number): Promise<Result<User>> {
  try {
    const user = await fetchUser(id);
    return { ok: true, value: user };
  } catch (e) {
    return { ok: false, error: e as Error };
  }
}

// =============================================
// 4. 串行 vs 并行（AI 常犯的错）
// =============================================

// ❌ 错：串行 await（慢 10 倍）
async function slow(items: number[]) {
  const results = [];
  for (const id of items) {
    results.push(await fetchUser(id));   // 每个 await 等前一个完成
  }
  return results;
}

// ✅ 对：并行
async function fast(items: number[]) {
  return Promise.all(items.map(id => fetchUser(id)));
}

读懂异步函数签名的 3 个关键

① 返回类型标注

// 看到 async 函数签名，先看返回类型
async function fn(): Promise<X> { ... }
//              ^^^^^^^^^^^^^^^
//              → 调用方拿到的就是 Promise<X>

async function fn2(): Promise<void> { ... }
//              → 不关心返回值，只关心"完成"

② 错误如何表达

// TS 约定：async 函数抛错 = Promise reject
// 调用方必须 await try/catch 或 .catch()

async function risky(): Promise<string> {
  throw new Error("boom");
}

const v = await risky();        // throw 同步冒泡
risky().catch(e => console.log(e));   // 异步捕获

③ void vs Promise<void>

// 这是 callback，调用方不等
function cb(fn: () => void) {}

// 这是 async，必须 await
async function acb(fn: () => Promise<void>) { await fn(); }

并发原语速查

API行为失败时
Promise.all([...])全成功才成功任一失败立即 reject
Promise.allSettled([...])等全部不失败，返回每项 status
Promise.race([...])第一个完成的胜出胜出那个 reject 就失败
Promise.any([...])第一个成功的胜出全失败才 reject (AggregateError)
vibe coding 实战：
  • 写函数签名：标注 Promise<Result<T>> 而不是 Promise<T>，让 AI 写错误处理而非抛异常
  • 看 Next.js 服务端组件：async function Page() { const data = await fetch(...); } 是默认模式
  • AI 写串行 await = 慢 10 倍。看到 for...of + await 立刻质疑能否改成 Promise.all
  • 提示 AI 用 Result<T>：错误不要 throw，让上层显式处理（vibe coding 友好）
